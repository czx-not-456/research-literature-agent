# 文献库 MVP 设计与验收

2026-11-21 用户确认暂停剩余的平台可行性验证，把阶段三和阶段四的首批文献库开发合并。首批交付与剩余目标的状态见 [项目状态](../../PROJECT_STATUS.md)。

用户在课题视图导入 PDF。服务校验文件尺寸、类型和页数，解析逐页文本，从 PDF 属性及首页可识别的标记提取元数据。Title 缺失时回退到第一页候选文本或文件名。作者、摘要、关键词、年份和 DOI 都允许留空。来源分为 PDF 属性、开篇文本、文件名和手动录入。扫描或损坏页保留原件，文本状态可区分为空、提取失败和被截断。

采用 Flask + 服务端 HTML + SQLite，作为本次单用户 MVP 的可撤销实现选择。浏览器不依赖线上资源。SQLite 保存课题、文献和逐页文本，原件作为 BLOB 同一事务写入。课题内用 SHA-256 对完全相同的文件去重；删除文献同时删除该文献的页文本。文本检索采用参数化的子串匹配，命中页取第一条，规模变大后再评估索引。

PDF 详情以物理页码生成 `?page=...` 深链，并用 PDFium 渲染所选页。用户可在原件和抽取文本之间核对，并使用原件链接在新标签页打开内建 PDF 查看器。全文阅读、印刷页码、坐标和 OCR 单独处理。没有文本的页会显示原因，不生成内容。

供未来工具侧调用的只读契约为 `GET /api/v1/documents/{document_id}/pages/{number}`。响应包括 UUID、题名、物理页码、页文本、提取状态和本地来源链接。后续通过受鉴权的服务适配器接入 AgentArts，Web 业务层维持文献存取与证据回溯，AgentArts 负责正式智能体编排。此端点目前只在本机运行；它提供页级来源，不能自动判定论文是否支持某个结论。

本阶段验收范围：

| 验收点 | 预期 |
| --- | --- |
| 创建课题和导入 | 中英文 PDF 能真实解析；不合规、已加密文件有反馈 |
| 原件和页文本 | 上传与下载字节一致；可按页访问并提取该页文本；不存在的页返回 404 |
| 资料管理 | 编辑及分类可持久保存；重复文件不会覆盖；删除同步清理页文本 |
| 检索 | 可按标题、作者、DOI 等字段、分类及原文检索，原文命中链接正确 |
| 持久化 | 用同一数据库重新启动应用后仍能找到记录 |
| 工具边界 | 提供可复现的页级 JSON，云端接入和身份验证留待后续联调 |

剩余的问答、引用支持分类、对比矩阵、调研报告和在线文献导入继续保留在开发计划中。


## 实测结果

Windows 11、Python 3.12.4 环境运行六项集成测试，全部通过。中英文样本用 ReportLab 生成，测试对真实 PDF 文件执行解析和浏览，不把样本元数据当作真实论文检索。另从 arXiv 读取公开论文《Attention Is All You Need》验证 15 页解析、第二页文本、标题和摘要脚注边界。Chrome 本地验证文献列表、第二页原文预览与窄屏布局。 [测试证据](evidence/verification.json)
